# 开源项目

我花了两周，给 Django 做了一款“零侵入”的缓存外挂

📅 2026-04-30 · 🕒 7分钟阅读

Redis 这个词，我听过很久了。但一直觉得“那是大厂才用的东西”。

直到有一次接的单子，MySQL 被查得嗷嗷叫，我才开始认真看缓存。

然后我发现一个很尴尬的问题：网上很多的方案，都默认你懂 Redis、懂缓存一致、懂降级策略。

但我只想让项目快一点，不想学这么多啊。

于是就有了 qc_redis——一个 Django 外挂，装上就能用，业务代码一行不改。

🎯 核心理念
pip install qc_redis
INSTALLED_APPS += ['qc_redis']
你的 Django 项目自动获得缓存能力。
读自动缓存，写自动失效。
不需要改任何业务代码。

一、为什么会有这个项目？

说实话，我不是 Redis 专家。我就是一个写 Django 接单的普通开发者。

项目并发上来了，MySQL 扛不住，我开始搜“Django 缓存”。

结果是这样的：

  • django-redis：告诉你“怎么连 Redis”，但缓存什么、怎么缓存，你自己写
  • django-cachalot：思路接近，但没考虑缓存雪崩、没考虑降级
  • 网上教程：全是“手写一个缓存装饰器”

没有一个是：装上就能用，不用写代码。

说白了，小团队想用缓存，必须先成为 Redis 专家。这不是工具，这是第二次开发。

二、那我自己做一个

我不想做“通用缓存中间件”，我只想解决 Django 这一个场景。核心就三件事：

  • 读自动缓存：ORM 查询结果自动存 Redis
  • 写自动失效：数据变化后自动删缓存
  • Redis 挂了不影响业务：自动降级回 MySQL

实现方式也不复杂，全是 Django 自带的能力：

1. 读：重写 Manager 的 get() / filter()
   → 先生成 cache_key
   → 查 Redis
   → 命中就返回，没命中就查 DB 并写入

2. 写：监听 post_save / post_delete 信号
   → 数据变化后自动删缓存
   → 延迟 200ms 再删一次（防并发脏读）

3. 降级：所有 Redis 操作 try-catch
   → 连不上就直查 DB，业务不中断

说白了，就是把“你会手写的那套缓存逻辑”，做成一个外挂。

三、现在做到哪了？

核心链路已经在我自己的接单项目里跑通了：

  • ✅ Signal 拦截 + Manager 注入
  • ✅ 延迟双删（200ms）
  • ✅ YAML 配置 + 热重载
  • ✅ 降级模式（Redis 挂了直接查 DB）
  • ✅ 基础 stats 命令行
  • 🚧 Web 监控面板（进行中）
  • 🚧 布隆过滤器（计划中）

代码已经在 GitHub 上了：https://github.com/RaM-bugourp/qc_redis

🧪 你可以现在就试
pip install qc_redis
INSTALLED_APPS += ['qc_redis']
python manage.py migrate qc_redis
然后去你的 Model 列表页刷新两次。
你会发现：什么都没改，但变快了。

四、适合谁？不适合谁？

  • ✅ 10-50 人团队，并发上来了，没空天天折腾缓存
  • ✅ 读多写少的业务（内容型、电商商品页、配置中心）
  • ✅ 不想学 Redis、不想写缓存代码的人
  • ❌ 写密集型业务（缓存收益不大）
  • ❌ 强一致性金融场景（延迟双删是最终一致）

五、最后说点实话

这个项目不是我灵光一现的产物，是接单被 MySQL 慢查询折磨后，不得不造的轮子。

因为我懒，不想在每个项目里手写缓存。因为我菜，记不住那么多缓存策略。

如果你也被同样的问题折磨过，欢迎来 GitHub 点个 ⭐️。

企业版（Web 配置 + 监控）可能会收费，那是后话。先把东西做出来再说。

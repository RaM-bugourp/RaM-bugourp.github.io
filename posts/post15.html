# Agent设计

关于Agent开发：六个设计核心与记忆系统的本质

📅 2026-08-18 · 🕒 3分钟阅读

不难发现，Agent 协作的比重和地位正在不断上升。

主要原因从我的角度来说，并不是模型本身，而是因为自动化任务的需求越来越多，同时大部分人并不擅长 prompt 或者 harness 工程——做不到为 LLM 编排清晰合理的规划以及执行路线。

所以 Agent 协作应运而生，用于任务前预编排工作流并验证可行性。当然受篇幅限制，我们今天只讨论 Agent 开发本身。

Agent 的设计核心有六个

分别是：感知、推理、规划、行动、记忆、反思。

你会发现，不论围绕哪一个进行设计，它都似乎是 Agent 不可替代的一部分：

  • 如果感知机制粗糙，会导致上下文污染，噪声过多，后续所有内容都是无效推理；
  • 如果推理没有约束和方向把控，会导致污染堆积，影响方向；
  • 规划决定了任务成果的上下限，如果你不是为了单纯测试 LLM 的 plan 水平，不要完全让它负责，而是人定拓扑，LLM填空
  • 记忆与反思看似不重要，但在长期任务和多轮任务中，Agent 区别于 LLM 的地方正是自我迭代。
  • 至于行为则是上述内容的具体表现和验证，但是在考虑Agent-环境关系时，却是最麻烦的一步

LLM 的边界在哪里

总体来说，你可以这样理解：LLM 会推理，但推理不可能完全正确，而是方向上符合逻辑、存在一些小的逻辑漏洞。在长推理任务下，这些小的逻辑漏洞会被它自己视为正确的结论，然后拿着这种错误结论继续推理，最后不断堆积，导致整个任务逻辑崩溃。

所以我们需要管理上下文、约束推理、进行剪枝，同时建立记忆系统。

记忆系统 vs 一份总结文档

你可能会想到：现在很多模型都有总结功能，每一轮工作下来都能总结汇报，我把汇报清洗筛选成 markdown 文档供 LLM 调用参考，这与 memory system 的本质区别是什么？

这就是你认识 Agent 的第一步。

你可以粗略地把 Agent 看做一个人
markdown文档是放在桌上的笔记本，你每次要用都得翻一遍；memory system是大脑自带的记忆归档和调取能力，该忘的忘，该记的记，该关联的自动关联

研究 Agent 要考虑的问题

上面这些内容已经足够搭建初步认知了。如果你感兴趣，可以按照这个分类继续研究 Agent 的设计以及需要考虑的问题：可靠性、性能问题、成本问题、调试问题、安全问题、可观测性以及评估问题。
